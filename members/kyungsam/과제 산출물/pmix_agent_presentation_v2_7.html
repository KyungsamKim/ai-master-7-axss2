1. Agent 소개

어떤 Agent를 만들어야 하는가 — P-Mix & 수익성

PP-Mix (Product Mix)
기업이 시장에 제공하기 위해 생산하거나 판매하는 모든 제품 계열과 품목의 총체적인 집합(배합)
  • 현재 과업에서는 DRAM / NAND 단품 기준으로 P-Mix 구성
  • 제품 계열 · 품목 단위의 배합 변화가 분석 대상
₩수익성
판매 수량 × 원가 × 수율 → 매출액 · 영업이익
  • 세 가지 항목을 통해 매출액과 영업이익을 산출
  • 산출된 값이 곧 수익성 지표

6. Agent 차별성

요구사항을 어떻게 구현했나

1Ontology
1하이닉스 DRAM / NAND 제품을 실제 속성 Code Level에서 이해할 수 있도록 객체화·구조화, 실제 데이터 Enum화 (Dimension)
2수익성 지표는 제품 Level, 지표에 따라 구분 (Measure)
3제품의 의미와 수익성 계산식을 Ontology 기반으로 Agent가 이해
2집계 처리 엔진
1Agent Layer와 MCP 집계 처리 엔진 역할 분리
2계산은 집계 처리 엔진이 담당
3100% 계산 결과를 신속하게 처리
3데이터 보안 체계 준수
1단순 기능 검증이 아닌 SKHy Agent Workflow 개발 Tool 준수 (LangGraph 버전이 낮음)
2LLM이 연결된 시스템은 직접 DB에 접근 불가
3OPA 테이블 컬럼 혹은 호출 Tool 기반으로 Agent별·사용자별 권한 체계 구축 대응

9. Lesson Learned

이번 과제에서 얻은 것

1
정확하고 복잡한 계산 로직의 System Agent 사례
  • 판단과 추론은 Agent Layer가, 계산 로직은 MCP Layer가 담당
2
검증 가능한 체계와 데이터 정비 우선
  • 성공적으로 Agent를 구축하기 위해선 요구 기능별로 검증 가능한 체계가 먼저 마련되어야 함
  • 그보다 앞서 Agent에 맞춘 데이터 체계 구축이 선행되어야 함
3
보안 표준 준수가 설계 제약
  • 하이닉스 Workflow 개발 Tool 준수
  • DB 접근 및 OPA 등 보안 체계 준수
  • 설계 제약을 고려한 아키텍처 설계
4
다른 Agent 확장
  • AI 기반 G-SCM의 방향성에 대한 모범답안 제시
  • G-SCM뿐 아니라 다른 도메인 영역에도 적용 가능한 사례
